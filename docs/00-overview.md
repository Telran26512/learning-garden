# AI Learning Garden — 项目概览与开发文档

## 1. 这是什么

一个**多用户的 AI 学习社区平台**。每个用户维护自己的 AI 学习历程,覆盖数学、机器学习、强化学习,并把三类核心材料打通:

```text
数学推导  ↔  可运行代码  ↔  论文原文
```

用户可把内容设为公开,公开内容汇聚成社区——可浏览他人的学习历程、评论、讨论、互相关注。

- **形态**:完整社区(共享内容 + 评论 + 讨论 + 协作)。
- **策略**:先小范围(自己 + 朋友)起步,架构预留公开注册的接缝。

完整功能规划见外部文档 `ai_learning_website_feature_plan.md`。本 `docs/` 是落地为工程的架构与规范文档。

## 3. 独立项目与仓库边界

完全独立的项目:自有仓库、自有部署。结构不照搬任何已有项目,完全按本项目自身需求设计(理由见 [01-architecture.md](./01-architecture.md))。

仓库采用 **multi-repo**:

- `ai-learning-garden` / `ai-learning-garden-docs`:项目总控与文档仓,维护架构、路线图、规范、数据模型、跨仓联调说明。
- `ai-learning-garden-web`:前端代码仓,维护 Next.js 单应用,独立部署到 Vercel。
- `ai-learning-garden-api`:后端代码仓,维护 Go 模块化单体、数据库迁移与 API 契约,独立部署为容器服务。

拆仓只改变工程仓库与发布边界,不改变系统架构:`web` 仍是一个前端应用,`api` 仍是一个模块化单体,二者只通过 REST `/api/v1` 通信。

## 4. 开发哲学(硬约束)

高于一切技术决策,违反它们的"好设计"一律不采纳:

1. **学习优先,网站第二。** 花在建站的时间 ≤ 总学习时间的 20%。
2. **内容驱动功能。** 没有产生学习内容就不写承载它的功能。不为"以后可能用到"提前编码(YAGNI)。
3. **能慢,不能断。** 进度以"完成的交付物数量"衡量,不以日历周衡量。
4. **多用户地基现在做,社区功能分期做。** 认证、用户体系、内容归属、多租户隔离是**地基**——后补等于重写,M0 就要有;评论、讨论、动态流是**上层功能**——随时可加,等到真有人用了再建(对应"先小范围")。
5. **内容可移植。** 内容入库后,靠后端的导出接口(导出为 Markdown/JSON)保证随时可迁移、不被锁死。

## 5. 一句话架构

> 8 个学习模块是"同一份内容数据的不同视图",模块之间不直接通信;"多用户"与"社区"是在这之上叠加的**归属/可见性维度**与**社交层**。后端是按领域硬隔离的模块化单体。
