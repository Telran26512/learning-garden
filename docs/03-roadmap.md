# 开发路线图

> 区分两个 roadmap:
> - **学习路线图**(52 周课表)= 学习内容,见 feature plan 第 12 节。
> - **本文档**(开发路线图)= 网站本身怎么一步步建出来。

## 1. 核心原则

1. **地基先行,功能分期。** 多用户地基(认证、归属、多租户、管理员角色)M0 就建;社区功能(评论、讨论、动态流)M4 才建;后台治理功能(举报、审核、防滥用)M6 才完整建设——后补地基等于重写,后加功能很轻松。
2. **里程碑由学习/使用需求触发,不由日历触发。** 一个功能只在"已经有内容/有人需要它承载"时才动工。
3. **每个里程碑都是可用闭环。** 任何里程碑结束时系统都能正常使用。
4. **受 20% 时间预算约束。** 见 [00-overview.md](./00-overview.md) 第 4 节。里程碑欠着不阻塞学习。
5. **垂直切片。** 每个里程碑打通 web→api→DB 的一条窄竖切,不水平堆层。

## 2. 里程碑

### M0 — 地基

**目标**:多用户地基立起来,但不含社区功能。这是唯一"必须一次做对"的里程碑。

- 初始化三个仓库的职责:`docs` 总控仓、`web` 前端仓、`api` 后端仓
- `web` + `api` 脚手架分仓建立,并跑通本地联调
- PostgreSQL、对象存储接入归 `api` 仓
- **`identity` 模块**:注册、登录、会话、角色(`user`/`admin`)——多用户从第一天就在
- **`content` 模块基础**:概念实体的 CRUD,带 `owner_id` + `visibility`
- `media` 模块:文件上传基础
- **后台管理系统地基**:`web (admin)` 路由保护、管理员占位工作台、后端 service 层 `role='admin'` 授权规则
- 数据库迁移工具、REST 契约初稿、`web` 分层 ESLint 规则、`api` `depguard` 模块边界规则
- 分仓 CI:`web` 跑 lint/typecheck/test;`api` 跑 lint/depguard/go test/迁移校验
- 交付:能注册登录、能创建一条 private 概念并看到它

### M1 — 个人学习闭环(MVP)

**触发**:学习接近第 7 周(线性回归)前。**目标**:在多用户地基上跑通**你自己**的学习闭环。

- `web (workspace)`:可勾选的 Roadmap 清单页
- `web (workspace)`:一个完整的「线性回归」三栏概念页——数学(KaTeX)/ 代码(`<RunnablePython>` 跑 numpy)/ 论文
- `web (studio)`:上传/编辑自己的内容
- `learning` 模块:任务勾选、概念掌握状态
- `runtime/`:`PythonRuntime` 接口 + Pyodide
- 内容默认 `private`
- 交付:你能完整使用这个学习 OS,此后每周产出 = 上传一条新内容

### M2 — 内容扩展 + 公开浏览

**触发**:内容积累到十几条时。

- 概念/论文/实验的列表页与详情页通用化
- `visibility=public` 内容可被他人浏览;`web (community)` 浏览入口
- 用户主页(`identity` 的公开资料 + 此人的公开内容)
- `relation` 模块:反向链接 UI
- `<PaperCode>` 组件(框架代码挂 Colab)

### M3 — 复习模块

**触发**:学习满 3–4 周、有足够内容值得复习。

- `learning` 模块:复习卡、简化 SM-2、今日到期队列
- 从内容正文 `::card` 标记自动抽卡
- `web`:`/review` 翻牌页 + 三档自评

### M4 — 社区社交层

**触发**:**先小范围那批朋友就位、准备好用了。** 不要在没人时先建。

- `social` 模块:评论、讨论、关注、动态流、通知
- `web (community)`:讨论区、动态流、通知中心
- 这是"完整社区"真正成形的里程碑

### M5 — 知识图谱 + 作品集

**触发**:概念量大到线性列表不够看。

- 此时才为图谱可视化选型(React Flow / Cytoscape.js)
- `relation` 生成依赖图;`web`:知识图谱、作品集聚合视图

### M6 — 审核与开放注册

**触发**:决定向公众开放时。

- `web (admin)`:后台管理系统正式版,包含举报队列、内容审核、评论/讨论管理、用户查看、注册控制
- `moderation` 模块:举报、审核动作、管理操作日志、防滥用、限流
- 管理端 API 契约:`/api/v1/admin/*` 或等价管理端点,所有写操作必须校验 `role='admin'`
- 开放公开注册
- 内容导出接口完善

## 3. 与学习计划的对齐

| 学习进度 | 对应开发里程碑 |
| --- | --- |
| 开工 | M0 地基 |
| 第 7 周前(线性回归) | M1 个人学习闭环 |
| 第 8–12 周 | M2 内容扩展 + 公开浏览 |
| 第 3–4 周起持续 | M3 复习(与学习并行) |
| 朋友就位后 | M4 社区社交层 |
| 阶段 1 之后 | M5 图谱 + 作品集 |
| 决定公开时 | M6 后台管理系统正式版 + 审核 + 开放注册 |

## 4. 不做的事

- M0 不把 8 个模块目录全建空壳——用到哪个建哪个。
- M4 之前不写任何 `social` 模块代码。
- M6 之前不做完整后台审核工作流;M0 只保留管理员角色、后台入口和授权地基。
- 不追赶里程碑进度;里程碑欠着不影响学习(见 feature plan 第 15 节失败预案)。
- 不在用户量到来前做缓存、队列、分库等伸缩性优化。
